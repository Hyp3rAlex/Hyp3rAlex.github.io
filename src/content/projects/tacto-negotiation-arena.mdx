## Summary

Tacto set the challenge for a weekend hackathon in October 2026: build a buyer agent for a fictional pump maker. The agent negotiates by message with one to three supplier bots, exchanging term sheets (unit price, payment term, lead time, volume and similar fields), and then accepts one standing term sheet or walks away. Nobody may step in during a run. Each thread allows ten buyer messages and sixty seconds per message.

A case is scored on total cost in euros, not unit price: `(C_open − C_deal) / (C_open − C_best)`, clipped to 0–1. A deal that breaks a must-have scores zero. So does ending without a deal when there is no alternative.

I led our team of three. We built a rule-based agent in Python on top of Tacto's starter kit: every decision is arithmetic on the term sheets and the thread state, and no language model is called at negotiation time. In the hosted practice evaluation the team's submitted agent reached agreements in 10 of 10 cases with a mean score of about 0.72.

My own technical work is the constraint validation and enforcement around that agent: a guard layer that forces every outgoing term sheet to satisfy the must-haves, verifies every accept, and keeps a thread alive while a sensible move is left.

Every agent in the repository implements one method, `decide(case, threads)`, and returns one message for one supplier: up to three term sheets, an accept of a standing sheet, or a walk-away. The submitted agent is four objects wrapped around each other: `EvidenceAgent(HealthScope(GuardedAgent(BetterAgent())))`.

Per turn, a decision passes through three stages:

1. **Constraint checks.** A term sheet is a candidate only if it has a price, keeps every must-have (`{field, op, value}` evaluated on the terms the deal would close on), costs less than the buyer's alternative and no more than the best opening quote. These predicates come from the starter kit.
2. **Concession logic.** `BetterAgent`, implemented by my teammate Niko, picks an opening anchor below the supplier's quote and then matches the supplier's last move, sending up to three term sheets per message.
3. **Acceptance.** The agent accepts a standing sheet only if it passes the checks and no other thread holds a cheaper one. A final offer from the supplier or the last allowed message relaxes how much margin it demands.

Each supplier thread is a small state machine driven by the supplier: `open` stays open or becomes `final_offer`, `agreed`, `walked_away` or `no_bid`. The buyer can counter, send text, accept a standing sheet (which closes the whole case with a deal) or walk away (which closes the whole case without one).

`GuardedAgent` receives the result of stages 2 and 3 and may replace it. `HealthScope` sets a supplier-health estimate for everything inside it, and `EvidenceAgent` rewrites only the message text to cite facts from the challenge's data package; it never touches term sheets or actions.

## Engineering decisions

### Force must-haves into every sheet, then force them again

The commit that introduces the guard records the diagnosis from the first twenty practice sessions: four of ten cases per run ended without a deal, and the pattern was the same in each. On cases with a must-have, no agent ever asked for it in a term sheet. The kit's `complete_offer` snaps each value to the nearest allowed option, which could land on an option that breaks the must-have; the agents' own safety checks then rejected every sheet they produced, and they walked away or ran out of rounds.

The guard commit adds a function that every agent can call on any sheet, instead of patching each agent's sheet builder:

<p class="src">agent/arena_kit/guard.py:54-69 @ 700cf95</p>

```python
def satisfy_must_haves(case, terms, standard=None):
    """A copy of `terms` with every must-have on a negotiable field satisfied, completed to a valid
    sheet. Must-haves on fields we cannot negotiate are left alone."""
    must = [m for m in case["buyer"].get("must_haves", []) if m["field"] in case["negotiable"]]
    result = dict(terms)
    for m in must:
        cur = result.get(m["field"])
        cur = snap(case, m["field"], cur) if cur is not None else cur  # complete_offer snaps it later
        result[m["field"]] = cur if _fits(m, cur) else _must_have_value(case, m, cur)
    result = complete_offer(case, result)
    for m in must:  # a gap filled from the plan, or a snap, may have broken it again
        if not _fits(m, result.get(m["field"])):
            result[m["field"]] = _must_have_value(case, m, result.get(m["field"]))
    if not must_haves_ok(case, result, standard):
        log.debug("guard: must-haves still fail after fixing %s", result)
    return result
```

The value is checked after snapping, not before, because a value that fits as typed can snap onto one that does not. When a field is violated the guard picks the boundary option (the largest allowed value for `<=`, the smallest for `>=`), which asks the supplier for the least it can.

The weak spot: the boundary option is the cheapest concession to request, not necessarily the cheapest outcome for the buyer, and a must-have on a field that is not negotiable cannot be fixed at all. The function logs that case and returns the sheet anyway.

### Wrap any agent instead of fixing each one

By Saturday evening all three of us had agents in the repository. A wrapper on the `decide()` contract protects all of them, including the ones written later, which is how it ended up around the submitted agent. `GuardedAgent` branches on what the wrapped agent returns:

- an **accept** is verified: the thread is live, the id is the supplier's standing sheet, the must-haves hold and the cost is below the alternative. An accept of an unmoved opening quote before we have written anything is deferred by one counter.
- **term sheets** get their must-haves forced. On the last allowed message, a price below the supplier's standing price is replaced, because a refused push ends the case without a deal.
- a **walk-away, an exception or an empty decision** goes to `_keep_going`:

```python
    def _keep_going(self, case, threads, preferred, reason):
        """Rule d: never walk while something sensible is left."""
        close = closing_move(case, threads)
        if close["message"]["action"]["type"] == "walk_away" and reason == "delegate wanted to walk" and self._hopeless(case, threads):
            self.log.info("%s guard: walk away stands (every thread is final, no counter beats the alternative)", self._case_id)
            return close
        if close["message"]["action"]["type"] == "accept":
            asid = close["supplier_id"]
            if (moves_left(case, threads[asid]) <= 1 or not self._eligible(case, threads, asid)
                    or self._supplier_moved(case, threads, asid)):
                self.log.info("%s guard: accept a safe standing sheet (%s)", self._case_id, reason)
                return close
        live = [s for s in live_threads(threads) if self._eligible(case, threads, s)]
```

If nothing safe can be accepted, the guard sends the supplier's own standing sheet back with the must-haves satisfied ("we can proceed at your price if the terms below work for you"). That counter is bounded: two per thread, one after a final offer. Every intervention writes a log line with its reason.

The trade-off is that the guard overrides the judgement of the agent it wraps. A walk-away that was correct for a reason the guard cannot see is turned into two more messages. The guard also keeps a per-case counter in memory, which is state the rest of the design avoids.

### A stateless confidence index

An earlier commit of mine implements a different idea: estimate from the thread how close a supplier is to its floor, and concede faster when it is close. The index starts at 1.0 and subtracts hand-set penalties: a last concession near zero, a shrinking concession, floor wording in the message (sixteen fixed English and German phrases such as "final offer" or "no room"), contradicted claims, timeouts, a shorter validity period. It is recomputed from the thread on every turn, so it survives a crash and restart.

```python
def effective_time(t, conf):
    """conf 1 keeps the curve, conf 0 jumps to the final target."""
    return 1.0 - (1.0 - t) * conf
```

Three agents used it; one bends a teammate's time-based concession curve with `effective_time`. The index is not part of the submitted chain: its weights are hand-set constants, the kit's scripted simulator gives no floor signals for it to react to, and on the hosted practice arena the confidence-based router closed six of ten cases (mean 0.21) before the guard existed. The stateless design is the part worth keeping.

### Measure on the practice arena, and revert when it says no

My own top-level agent, `final`, subclasses a teammate's reciprocal agent and changes four things: no throttling of our concession steps (the supplier bots mirrored small steps with equally small ones and the thread froze), silent suppliers are skipped instead of walked away from, a sheet that only fails a must-have is rescued before walking, and the last message is always an accept or a close.

In ten practice sessions `final` closed 10 of 10 cases with a mean score of 0.58. Niko's `better` agent reached 0.72 on the same cases and is the agent the team submitted, wrapped in the guard. Petra's `combined` agent builds on `final`.

The concession rule of `final` is short: open at 80% of the supplier's price (never below 75%, never above the price paid today), then close a growing share of the remaining gap each round, staying 5% below the supplier until the last two messages.

```python
    def _price(self, case, events, p):  # called by the inherited _sheets
        sheets = [m["term_sheets"][0]["terms"].get("unit_price") for m in _mine(events) if m.get("term_sheets")]
        mine = [x for x in sheets if x]
        if not mine:
            cur = case["buyer"].get("current_unit_price")
            return max(ANCHOR_FLOOR * p, min(self.anchor * p, cur or p))
        frac = min(FRAC_MAX, FRAC0 + FRAC_STEP * len(mine))
        step = max(frac * (p - mine[-1]), MIN_STEP * p, _tick(p))
        move = self._their_move(events)
        if self.match is not None and move > 0:
            step = max(MOVING_MIN * p, _tick(p), min(step, self.match * move))
        top = p if moves_left(case, events) <= 2 else p * (1 - KEEP)
        return max(mine[-1], min(top, mine[-1] + step))
```

Decisions followed the measurements. An opening anchor at the buyer's current price lost on two practice cases and was removed five minutes after it was committed, with the measured loss in the commit message. A rewrite that bargained in supplier-value space scored 0.56 against 0.58 and stayed on a branch.

## Limitations

- **Practice evaluation only.** The measurements are from the practice arena and a local simulator; no live-final result is recorded.
- **The supplier bots were deterministic.** They send a final offer at a fixed message number, and several timing rules rely on that. Against a person those rules would need rework.
- **The agent reads structure, not language.** A supplier's objection registers only when it changes a term sheet.
- **The guard is conservative by construction.** It sends the supplier's own price back with corrected terms; it never improves the price, and it can spend up to two of ten messages doing so.
- **Multi-supplier runs are not bit-reproducible offline**, because messages to several suppliers are sent concurrently. Single-supplier runs are, which is why the replay uses one.
- **Not fully verifiable from outside.** The 72 skipped tests need Tacto's data package, the hosted arena or an optional extra, and the repository has no licence file or continuous integration.

## What I would do next

- Measure the guard in a controlled experiment: the same agent with and without it, on the same cases, several sessions each.
- Let the guard reason about cost as well as validity: when several options satisfy a must-have, choose by total cost instead of always taking the boundary.
- Calibrate the confidence index against recorded supplier behaviour before using it again.
- Derive the guard's counter count from the thread, so the wrapper is stateless like the rest of the chain.
